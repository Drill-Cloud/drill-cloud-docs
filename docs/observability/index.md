# Наблюдаемость Drill Cloud

Раздел описывает рабочие дашборды [Grafana Drill Cloud](https://grafana.drillcloud.ru/): какие вопросы они закрывают, как читать панели и когда переходить к расследованию. Это эксплуатационная инструкция, а не рекламное описание Grafana.

Скриншоты зафиксированы 10 сентября 2026 года за период «последние 6 часов» в часовом поясе `Europe/Moscow`. Значения на них являются примером; решение принимается по текущим данным и обычному уровню конкретного сервиса.

## Какие вопросы закрывает Grafana

- доступны ли UI и API контуров DEV, ALPHA и PROD;
- какой контейнер потребляет CPU, RAM или создаёт сетевой трафик;
- где появились ошибки: Backend, UI, MQTT-ingest или Monitor;
- работает ли PostgreSQL exporter и что происходит с базами `cloud-dev` и `cloud`;
- не является ли причиной проблемы сам сервер или система сбора метрик и логов;
- с какого момента началось отклонение и что происходило рядом по времени.

## Карта дашбордов

| Вопрос | С какого экрана начать | Куда перейти дальше |
|---|---|---|
| Всё ли доступно | **Обзор бизнес-контуров** | **Доступность**, затем нужный контур |
| Проблема только в DEV/ALPHA/PROD | Дашборд соответствующего контура | Раздельные логи Backend/UI/MQTT/Monitor |
| Нет свежих данных по установке | **Общие сервисы** и нужный контур | MQTT-ingest, Monitor, Backend, PostgreSQL |
| Ошибка или задержка БД | **PostgreSQL** | Backend-логи и логи PostgreSQL |
| Нагрузка сразу у нескольких сервисов | **Сервер** | **Docker-контейнеры** |
| В Grafana пусто сразу на многих панелях | **Состояние мониторинга** | Prometheus, Loki, Alloy и cAdvisor |
| Ошибка инфраструктурного сервиса | **Инфраструктурные логи** | Фильтр по stack/container |

## Карта контуров

| Контур | Frontend | Backend | Monitor | MQTT-ingest | PostgreSQL |
|---|---|---|---|---|---|
| DEV | `drill-cloud-frontend-dev` | `drill-cloud-backend-dev` | `drill-mqtt-ingest-monitor-dev` | общий | `cloud-dev` |
| ALPHA | `drill-cloud-frontend-alpha` | `drill-cloud-backend-alpha` | `drill-mqtt-ingest-monitor-dev` | общий | `cloud-dev` |
| PROD | `drill-cloud-frontend` | `drill-cloud-backend` | `drill-mqtt-ingest-monitor` | общий | `cloud` |

!!! important
    `cloud-dev` и Monitor-dev общие для DEV и ALPHA, а MQTT-ingest общий для всех контуров. Нагрузку или сообщение общего сервиса нельзя автоматически приписывать только одному окружению — всегда сопоставляйте время и идентификатор установки.

## Что считать нормой

- внешние проверки UI и API — `UP`;
- HTTP-коды штатных проверок — `2xx`;
- exporter и компоненты наблюдаемости доступны;
- число контейнеров соответствует ожидаемому составу стека;
- CPU, RAM, трафик и время ответа находятся около привычного уровня;
- у PostgreSQL нет deadlock, а возраст открытой транзакции не растёт непрерывно;
- в логах нет устойчивого потока одинаковых `error`, `fatal`, `exception`, `panic` или `failed`.

Фиксированных универсальных порогов для нагрузки нет: короткий пик может быть нормой, а небольшой, но постоянный рост — признаком утечки. Сравнивайте показатель с предыдущим стабильным периодом и моментом релиза.

## Когда бить тревогу

- PROD UI или API перешёл в `DOWN`;
- `DOWN` держится больше одного цикла обновления либо повторяется;
- резко уменьшилось число контейнеров;
- исчезли метрики сразу с нескольких экранов;
- RAM растёт без возврата, CPU остаётся высоким длительное время, заканчивается диск;
- в PostgreSQL появились deadlock, растут rollback или возраст старой транзакции;
- массово повторяется одна и та же ошибка в Backend, MQTT-ingest или Monitor;
- сертификату осталось меньше 30 дней; меньше 7 дней — срочная задача.
