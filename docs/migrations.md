# Миграции базы данных

Миграции хранятся в backend-репозитории `drill-cloud-backend` и применяются автоматически при старте приложения.

## Как добавить миграцию

1. Создайте SQL-файл в каталоге `migrations`:

   ```text
   migrations/0006_short_description.sql
   ```

   Используйте следующий свободный номер и короткое имя на английском.

2. Добавьте файл в конец массива `DB_MIGRATIONS` в `src/db/migrations.ts`:

   ```ts
   {
     id: '0006_short_description',
     fileName: '0006_short_description.sql',
   },
   ```

3. Пишите в SQL только изменение схемы или данных. Миграция должна выполняться без ручных действий и быть совместимой с уже работающей версией backend.

4. Не изменяйте и не удаляйте уже применённые миграции. Для исправления создавайте новую миграцию со следующим номером.

## Как проверить

Запустите backend на тестовой БД:

```bash
npm run start:dev
```

Убедитесь, что приложение запустилось, нужная схема или данные появились, а миграция записана:

```sql
SELECT id, applied_at
FROM public.schema_migrations
ORDER BY applied_at, id;
```

Также проверьте повторный запуск backend: миграция не должна выполняться второй раз.

## Что происходит при деплое

- каталог `migrations` копируется в Docker-образ;
- backend подключается к БД из `DATABASE_URL`;
- при старте создаётся `public.schema_migrations`, если её ещё нет;
- отсутствующие миграции выполняются по порядку из `DB_MIGRATIONS`;
- каждая миграция выполняется в отдельной транзакции;
- при ошибке транзакция откатывается, а backend не запускается.

Сначала проверяйте миграцию на DEV, затем на ALPHA и PROD. DEV и ALPHA используют общую БД `cloud-dev`, поэтому там одна миграция применяется только один раз. PROD использует отдельную БД `cloud`.

Перед изменением или удалением данных сделайте резервную копию БД. После деплоя проверьте лог backend и таблицу `public.schema_migrations`.
